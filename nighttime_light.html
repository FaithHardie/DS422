DS-422 Geocomputation: Kona Low Storms

Research question: How did the first Kona Low storm and second Kona Low storm differ in their impact on power outages on Oahu?

Sub questions:

  1. Regionally, how did the impacts differ?

  2. Did the outage patterns correlate with the storm’s paths?

Hawaii boundary

tigris defaults to NAD83 and Black Marble expects WGS84, so the reprojection is required. Honolulu County’s official boundary extends across the Northwestern Hawaiian Islands, so it is cropped to Oahu itself.

roi_hawaii <- counties(state = "HI", cb = TRUE, year = 2022) |>
  st_transform(4326) |>
  st_crop(xmin = -160.5, xmax = -154.5, ymin = 18.5, ymax = 22.5) |>
  filter(NAMELSAD != "Kalawao County") |>
  mutate(county = gsub(" County", "", NAME))

roi_sf <- roi_hawaii |>
  filter(county == "Honolulu") |>
  st_crop(xmin = -158.35, xmax = -157.60, ymin = 21.20, ymax = 21.75)

Pulling Black Marble rasters

VNP46A2 is the daily product. Each date is pulled individually and wrapped in tryCatch(), so one missing night does not kill the whole period. This matters because several March storm nights have no usable imagery.

Black Marble labels its layers t2026_03_10, so the names are forced back to ISO dates. Without that, later date matching silently returns nothing.

r_list <- list()

for (period in names(all_dates)) {
  dates <- all_dates[[period]]

  lst <- lapply(dates, function(d) {
    tryCatch(
      bm_raster(roi_sf = roi_sf,
                product_id = "VNP46A2",
                quality_flag_rm = 2,
                date = d,
                bearer = bearer),
      error = function(e) {
        message("No imagery for ", d)
        NULL
      }
    )
  })

  names(lst) <- as.character(dates)
  lst <- lst[!sapply(lst, is.null)]

  r <- rast(lst)
  names(r) <- names(lst)
  r_list[[period]] <- r
}

Masking

Everything from here stays on the raw radiance scale. Log transforms are applied only when a map needs them, and always fresh, never on top of an already-logged raster. Logging before computing change would turn absolute change into a log ratio and make percent change uninterpretable.

Period composites and change metrics

Percent change explodes toward meaningless values where the baseline is near zero, so dim pixels are masked out before dividing. The z-score divides by each pixel’s baseline standard deviation, which breaks down at pixels that barely vary, so those are dropped too.

period_mean <- list()
for (period in names(r_masked)) {
  period_mean[[period]] <- terra::mean(r_masked[[period]], na.rm = TRUE)
}

NOISE_FLOOR <- 5
meaningful <- period_mean$baseline >= NOISE_FLOOR
keep <- function(r) terra::mask(r, meaningful, maskvalues = FALSE)

percent_storm1     <- keep((period_mean$storm1 - period_mean$baseline) / period_mean$baseline * 100)
percent_storm2     <- keep((period_mean$storm2 - period_mean$baseline) / period_mean$baseline * 100)
percent_gap        <- keep((period_mean$gap    - period_mean$baseline) / period_mean$baseline * 100)
percent_storm2_gap <- keep((period_mean$storm2 - period_mean$gap)      / period_mean$gap      * 100)


baseline_sd <- terra::app(r_masked$baseline, sd, na.rm = TRUE)
sd_floor <- max(quantile(values(baseline_sd), 0.1, na.rm = TRUE), 1e-6)
baseline_sd[baseline_sd <= sd_floor] <- NA

z_score_storm1 <- keep((period_mean$storm1 - period_mean$baseline) / baseline_sd)
z_score_storm2 <- keep((period_mean$storm2 - period_mean$baseline) / baseline_sd)
z_score_gap    <- keep((period_mean$gap    - period_mean$baseline) / baseline_sd)

Percent change maps

geom_sf() is used for the boundary outline rather than geom_spatvector(), since roi_sf is an sf object and not a SpatVector.

map_change <- function(r, ttl, sub, lgd) {
  v <- values(r)
  lim <- max(abs(quantile(v[is.finite(v)], c(0.01, 0.99), na.rm = TRUE)))
  ggplot() +
    geom_spatraster(data = r) +
    geom_sf(data = roi_sf, fill = NA, color = "black", linewidth = 0.2) +
    scale_fill_gradient2(low = "blue", mid = "white", high = "red",
                         midpoint = 0, limits = c(-lim, lim),
                         oob = scales::squish, na.value = "transparent",
                         name = lgd) +
    labs(title = ttl, subtitle = sub) +
    coord_sf() +
    theme_void() +
    theme(plot.title = element_text(face = "bold", hjust = 0.5),
          plot.subtitle = element_text(hjust = 0.5))
}

Z-score maps

The z-score asks how unusual a storm value is given how much that pixel normally fluctuates, which surfaces darkening in quiet, stable areas that percent change can bury.

Did the island recover between storms? March 18 had a mean z-score of -2.28. A value near zero means the grid was substantially restored before the second system arrived, so the two storms can be read as separate events. A strongly negative value means the second storm landed on a grid still down from the first, and part of its measured impact is inherited rather than new.

Sub-question 2, storm paths. The storm-versus-storm map above shows which system darkened each part of the island more. Compare it against the rainfall and wind summaries in the NWS Honolulu March 2026 severe weather report to judge whether darkening followed each storm’s track.

Limitations

Radiance is a proxy for grid status rather than a measurement of it, so cloud attenuation during a Kona Low is indistinguishable from an outage at the pixel level. The coverage table above shows how much of the island each period actually delivered, and the pixels lost to cloud are disproportionately those under the heaviest rain, which biases against detecting the worst-hit areas. VIIRS also observes only once per night at roughly 1 to 2 AM local time, so an outage that began and resolved between overpasses leaves no trace. Finally, EAGLE-I outage reports are not yet published for 2026, so nothing here is validated against reported customer counts.
